# 質問データ作成ガイドライン

質問を追加・修正するときのルール。形式の定義は `src/data/schema.ts`、検査は `src/data/validate.ts`。

## 1. 基本原則

1. **事実とモデルを分ける**
   - 事実（`facts`）：発売・登場・放送の時期、国内の普及・流行時期、主な利用者層。**必ず出典を付ける**。
   - モデル（`model`）：事実から経験確率を計算するための設計値（年齢窓・経験率の上限など）。**推定であることと根拠（`rationale`）を書く**。
2. **出典で確認できない事実は登録しない**。発売年・流行年・普及率を推測で埋めない。
3. **発売年と流行年を混同しない**。流行・普及の時期は `peak`・`diffusion` に分けて書く。

## 2. 事実の状態（`status`）

| 状態 | 意味 | 条件 |
|---|---|---|
| `verified` | 出典の本文で直接確認した値 | `quote` に出典本文の該当箇所を書く |
| `derived` | 出典付きの事実・統計から、規則で導いた値 | `rule` に導出規則を書く（例：「生産数量が最大値の50%以上の期間」） |

事実に「推定（estimated）」は使えない（形式検査でエラーになる）。

## 3. 出典の信頼性

| 等級 | 基準 | 例 |
|---|---|---|
| A | 公式サイト・メーカー資料・官公庁の資料と統計 | 任天堂の沿革、財務省、文部科学省、内閣府の統計 |
| B | 信頼できる報道・専門メディア・業界の記録 | ファミ通、文春オンライン、新語・流行語大賞 |
| C | 二次資料（百科事典サイトなど） | Wikipedia |

- **信頼性Cの出典だけを根拠にした事実はエラー**（補助出典は単独根拠にしない。A/Bと併用するのは可）。
- 質問の信頼性は、各事実の「最も信頼できる出典」の中で最も低い等級（自動計算）。
- 出典は `data/sources.json` に登録し、事実からは ID（`src-…`）で参照する。確認日（`accessed`）を必ず書く。

## 4. 統計の扱い

- 統計は `data/statistics/` に転記し、元の公表資料を出典として登録する。
- 統計から期間を導く場合は、規則を `rule` に書き、`tests/unit/dataset.test.ts` に**統計から再計算して一致するかのテスト**を追加する。
- 家電の世帯普及率のように、統計そのものを確率として使う対象は `kind: "household"` とし、統計の最終年より後の扱い（`after`）を根拠付きで書く。

## 5. 質問の作り方

| 項目 | ルール |
|---|---|
| 選択肢数 | 主要選択肢は4〜6個。「覚えていない」は必ず付ける。「該当しない」は前提が当てはまらない人がいる質問にだけ付ける（どちらも数に入れない） |
| 経験型 | 「よく経験した／少し経験した／知っているが経験はない／知らない」の4種類を基本にする（文言は質問に合わせてよい） |
| 時代選択型 | 「小学生の頃」など**年齢を指定**し（`ageWindow`）、各選択肢に時代を表す対象を割り当てる。どの時代にも当てはまらない人のために「この中にはない」を付ける（全期間をカバーする場合は不要） |
| 重要度（`importance`） | 年齢以外の要因（性別・地域・趣味）で回答が大きく変わる題材は下げる（0.6〜0.8） |
| 関連質問 | 同じ情報を持つ質問は `group`・`relatedIds` で結ぶ（推理での二重カウント防止） |
| 文言 | 性別を前提にしない（例：「自分もはいていた・周りで流行していた」）。災害など心理的負担のある出来事は避ける。年の明記は、同名の別のもの（例：2回の東京オリンピック）と区別する必要がある場合に限る |

## 6. 作業手順

```bash
npm run validate:data     # 形式・整合性の検査（エラーがあれば終了コード1。CIでも実行）
npm run report:coverage   # 年代別経験確率と分析レポートを再生成
npm test                  # 統計からの再計算テストを含む
```

- `npm run report:coverage` は `data/generated/question-profiles.json`（質問ごとの年代別経験確率）と `docs/phase2/coverage-report.md` を上書きする。**手で編集しない**。
- レポートの「識別力が弱い年代」「類似質問」を見て、質問の追加・関連付けを判断する。

## 7. Phase 6（200問への拡張）で追加した運用ルール

| 項目 | ルール |
|---|---|
| 関連付けの判断 | 「類似質問」（年代別の経験確率の曲線が似ている組）でも、**別ジャンルで題材が無関係なら関連付けない**（年齢という共通の原因以外では独立した証拠のため）。同じジャンルで、家庭の経済状況・趣味・同じ文化圏（ギャル文化、バブル期のファッションなど）でも回答が連動しやすい組だけを `group`・`relatedIds` で結ぶ |
| 長く続いた作品・商品 | 長寿番組や現在も続く商品は、質問文で時期を限定する（例：「最初の放送当時（1966〜68年）」「声が大山のぶ代さんだった頃（2005年3月まで）」）。限定できない題材は採用しない |
| 新語・流行語大賞 | 受賞・トップテン入りした年を「その年に流行した」（`peak`）として使い、主催者ページの解説文を `quote` に書く。受賞の事実そのものは信頼性B（主催者の公表） |
| 1日〜数週間の出来事 | `kind: "event"` とし、開始と終了に同じ時期を入れる（例：開会式の日） |
| 世帯普及率 | 統計の最初の調査年より前は0とみなされる（例：プッシュホンは1987年から）。実際には少し普及していた場合は `notes` に書く。統計の最終年より後は `after` に根拠付きで書く |
| 1問で決まりすぎる質問 | 1つの回答だけで80%区間が20年未満になる質問は重要度（`importance`）を下げる（単体テストで検査） |
| 文言の長さ | 質問文は約60字以内、選択肢は約25字以内（小さいスマホで全選択肢がスクロールなしで収まるように） |
